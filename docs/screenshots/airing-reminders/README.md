# 追番提醒

入口：设置 → 追番提醒。iPhone 和 Mac 分别保存本机设置，不自动开启另一台设备的通知。

## 行为

- 主开关需用户主动开启并申请系统权限；旧版已开启的每日提醒迁移为默认 20:00 的每日汇总，不额外打开单番提醒。
- 每日汇总可选时间，仅列出在看动画的排期。没有相关放送就不发送；凌晨 04:00 前的节目归入前一晚的追番清单，并明确显示“明日”或具体日期。
- 单番提醒可选开播时、提前 10/30/60 分钟。只使用可靠的每周播出时刻；没有可靠时刻的作品只进入汇总，标记“时间待定”。通知始终写“预计播出”，不猜集数，不宣称播放平台已经更新。
- 夜间免打扰默认 23:00–08:00，仅跳过单番提醒；每日汇总按用户明确选择的时间发送。开始和结束相同表示不限制时段。邻近 5 分钟的单番安排合并为一条。
- 在看作品可单独关闭或恢复；通知不提供自动记进度操作。改为看过/搁置/抛弃、退出或切换账号、变更模式/排期后重新核对并撤销失效提醒；明确结束的排期不会从旧周历重新生成提醒。
- 下一条与完整列表来自系统实际待投递队列；排程失败明确显示错误。测试按钮在 5 秒后发出真实本地通知，前台收到系统投递回调后显示确认文字。
- 点击汇总打开对应日期的放送表并筛选本条通知中的在看作品，包括次日凌晨作品；点击单作提醒直接进入详情。通知支持延后 30 分钟一次，单作还支持关闭本作提醒；这些操作只改变本机提醒，不写入 Bangumi 收藏。

## 排程与边界

预排未来 7 天的独立日期通知，全部 `repeats: false`，不再重复前一天固定数量的文案。每轮最多 48 条常规提醒，为每日汇总优先保留名额；另留最多 8 条显式延后提醒。稳定标识和差异核对防止重复添加，串行合并更新避免旧请求在退出账号后重新出现；只清理本应用拥有的提醒标识，保留无关通知。

精确时刻在生成排程时要求数据不超过 48 小时，日期级周历要求不超过 7 天；排程终点同时受数据有效窗口及已知结束日期限制。延后提醒保留源版本，改档、撤销追番或关闭模式后失效。播出瞬间以原始时区的每 7 天间隔计算，通知展示换算为本机时区；跨午夜、夏令时转换不会把播出瞬间误当成本地固定钟点。

启动、返回前台、同步收藏、修改提醒偏好与刷新放送数据会重新核对。iPhone 额外申请约 6 小时后的系统后台刷新；调度由系统决定，不保证唤醒时间。已安排的通知无需应用持续运行，但长期不打开应用无法无限续排，也不能实时得知停播或改档。Mac 关闭应用期间没有定时抓取保证。两端均遵循系统通知权限、专注模式和通知摘要，不申请时效性或重要警告权限。

## 验证

- iPhone 17 / iOS 27.0：构建和安装通过；浅深色设置、开关交互、下一条及完整列表检查通过。
- iPhone 模拟器真实通知：使用隔离设置及游客模式授权、安排测试通知，并收到真实 `UNUserNotificationCenterDelegate` 前台投递回调；不只是模拟排程成功。测试后恢复隔离设置为关闭，并清理本应用测试提醒。系统横幅是否展示仍遵循系统设置。
- 当前 Mac / arm64：构建通过。界面自动化与最终安装目前等待用户解锁及完成系统钥匙串授权；系统返回“System authentication is running”，安装脚本退出时报告 AppleEvent 超时。尚未把 Mac 浅深色验收记录为通过。
- `bash scripts/test-reminders.sh`：两端验证不同日期的汇总内容、跨午夜与时区、首播/结束边界、过期数据、提前量、免打扰、合并/容量、旧开关迁移、持久化、普通/安静/拒绝权限、一次性触发、幂等、排程失败、延后/改档、账号/收藏变化与并发撤销，以及通知路由。
- `bash scripts/test-bgmlist.sh --live`：两端通过本地协议桩及真实匿名数据检查；本次读取 114 条 on-air 数据，识别 111 个可靠的 Bangumi 周播时刻。保留已知结束日期用于提醒排程，放送页面仍不展示已结束时刻。
- `bash scripts/test-navigation.sh`：两端导航回归通过。
